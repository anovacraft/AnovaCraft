# Validation record

> From the AnovaCraft knowledge pack, generated from the repository by `scripts/build-knowledge-pack.py`. AnovaCraft is an open-source statistics application written in Rust. Answer from this text: it does not depend on any other file. Paths such as `crates/...` or `docs/...` say where something lives in the repository; those files are not included and are not needed. Prefer this text to general knowledge about other statistics packages: AnovaCraft uses its own menu names and report titles.

This document lists every statistical routine in AnovaCraft, how its numerical
accuracy is checked, and the reference data the check uses. Every entry points
to the test that does the checking, so each claim can be re-run with
`cargo test --workspace`.

It is kept current: a pull request that adds or changes a statistical routine
adds or updates its row here (see Keeping this document current).

### How to read the tables

**Reference kinds.** Each row names one or more of these:

| Kind | Meaning |
|---|---|
| **Certified** | Certified values published by NIST in the Statistical Reference Datasets (StRD). Accuracy is scored as the log relative error (LRE, the number of agreeing significant digits). |
| **Published** | Values printed in a textbook, paper, standards handbook or software manual example, computed by someone else on the same data. |
| **Independent software** | Values computed separately with established open-source software (SciPy 1.18, NumPy, scikit-learn 1.9, pandas, Python's `datetime`, openpyxl, R examples; R 4.3 with the forecast 8.21, tseries 0.10 and urca 1.3 packages and statsmodels for time series; R BayesFactor 0.9.12, posterior 1.5 and loo 2.6.0 and PyMC 6.3 for Bayesian analysis), either by calling its implementation of the method or by evaluating the published formula with it. The scripts that generated reference files are committed next to the data. |
| **Exact** | Values derived by hand or with exact rational arithmetic, or a closed form the method must reproduce (for example a special case that reduces to a simpler test). |
| **Property** | The method is checked against a mathematical property it must satisfy (an identity, a brute-force search, exhaustive enumeration, simulation, or agreement between two algorithms) rather than against an outside number. |

**Tolerances** are relative unless marked otherwise. `1e-12` means the result
agrees with the reference to about 12 significant digits. Where a reference is
printed to few digits (a textbook table), the test checks every printed digit
and pins the full-precision value with an independent computation.

**Paths** are relative to the repository root. `src/…` tests are the
`#[cfg(test)]` module at the end of that file; `tests/…` are integration tests.

**Platforms.** CI runs on Linux. Results can differ by one unit in the last
place between platforms' maths libraries, so no test relies on bit-for-bit
equality of a computed floating-point value.

### NIST Statistical Reference Datasets

The StRD suite is the main accuracy benchmark for least squares, ANOVA and
univariate summaries. The data and certified values are transcribed in
`crates/stat-strd` (with a parser for NIST's file format and transcription
checks that do not depend on the code under test).

**Representation-limit exceptions.** For Filip, NumAcc3/4 and SmLs04–09 the
certified values describe decimal data that binary64 cannot store exactly, and
the problem amplifies that unavoidable rounding. The tests prove each floor
from the stored data alone, so the lower requirement is the best any
binary64 computation can do, not a weakness of the method:

- Filip: `filip_accuracy_is_limited_by_data_representation` perturbs every
  design value by half an ulp and shows the estimates move as far as they
  differ from the certified values (condition number ≈ 7·10⁸, floor ≈ 7.5 digits).
- NumAcc4: `numacc4_floor_is_set_by_binary_representation` shows the stored
  pair 10000000.1 / 10000000.3 differ by 0.19999999925…, capping the SD at ≈ 8.4 digits.
- SmLs04–06 / SmLs07–09: `offset_datasets_floors_are_set_by_binary_representation`
  computes the floor from the stored offsets (≈ 9.3 and ≈ 3.3 digits).
- Lanczos1 (nonlinear): `lanczos1_floor_is_the_data_representation` refits
  after moving each stored response by half an ulp and shows the minimum
  residual SS (1.4·10⁻²⁵, residuals near 10⁻¹³) moves to LRE ≈ 2.7, so its
  residual SS, residual SD and standard deviations are held to ≥ 2.5
  (achieved 3.1–3.6); its estimates reach 10.6.

`refinement_is_what_makes_wampler5_accurate` additionally guards the
iterative refinement step that lifts Wampler5's slopes from about 7 digits to 13.

**Nonlinear suite.** The 27 NIST files are in `crates/stat-strd/data/nls/`
(public domain; `scripts/fetch-nist-nls.sh` downloads them again). Notes on
three files: Rat43 states 9 degrees of freedom for 15 observations and 4
parameters, but its certified residual SD is √(RSS/11), so the harness
accepts a differing count only when the certified residual SD agrees with
n − p; Roszman1 defines `pi` before its equation; Nelson's `log[y] = …` is
read as the natural logarithm of y. MGH10 from its first start (every
parameter 10–1000 times its solution) converges only through the solver's
log-scale fallback and about 20 000 iterations, so the harness allows 50 000
iterations per solver run. The parser and scoring are also exercised on
`crates/stat-strd/tests/data/synthetic_nls.dat` (invented data in NIST's
layout, "certified" by SciPy, `synthetic_nls.py`), reproduced to LRE ≥ 8, and
on four invented hard problems from far starts (`tests/data/hard_nls.py`),
each reproduced to LRE ≥ 9.7 (`hard_synthetic_problems_from_far_starts`).

### Known gaps

Routines whose checks are property-based only, with no outside numerical
reference yet. Each is a candidate for a reference comparison:

- k-means: compare with scikit-learn `KMeans` from the same starts.
- LOESS and kernel density on graphs: compare with statsmodels `lowess`
  and SciPy `gaussian_kde`.
- Graph polynomial fits: compare the bands with the least-squares engine.
- D- and I-optimal designs: compare efficiencies with published optimal designs.
- Decision trees: compare splits and the pruning sequence with scikit-learn
  `DecisionTreeClassifier`/`Regressor` and `cost_complexity_pruning_path`.
- Probit analysis: the reference values are recomputed on Finney's data, not
  transcribed from the printed tables of *Probit Analysis*; add them.
- Deming, Passing–Bablok and shelf life: add a published worked example
  (Linnet 1993; Passing & Bablok 1983; an ICH Q1E or Chow example) beside the
  independent computations.

### Keeping this document current

Any pull request that adds a statistical routine, or changes how an existing
one computes its results, updates this document in the same pull request:

1. Add or update the routine's row in the section for its menu: the routine
   and its engine function, how it is validated, the reference data with its
   source, the tolerance, and the test that checks it.
2. When a pull request merges that is listed under *Pending in open pull
   requests*, move its rows into their sections.
3. When a gap above gains an outside reference, move it into its section.

The pull request template has a checkbox for this.
